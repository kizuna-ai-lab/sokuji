# Doubao AST 2.0 Voice Catalog — Design

**Date**: 2026-10-02
**Status**: Draft — brainstormed with the user 2026-09-28 → 2026-10-02, awaiting review of this file
**Base**: `main` at `a75b3825`; branch `worktree-ast2-fixed-voice` (commits `0e0599bf`, `96feb2ef`,
`e498b871`, the first #577 cut — §9 says what of it stays)
**Scope**: the `volcengine_ast2` provider, one shared field component, the extension manifest, the
locales, and a maintainer-only script. No other provider changes.
**Related**: discussion #565; issues #576 (probe) and #577 (this feature); the unified language codes
spec `2026-10-01-unified-language-codes-design.md` (app codes, the wire table, the global pair); the
voice library redesign spec `2026-09-16-voice-library-redesign-design.md` (the picker reused here).

## Summary

Doubao AST 2.0 today speaks every translation in the speaker's own cloned voice. #577 first offered
the two fixed voices the AST document names. This design replaces that with Doubao's whole public
TTS catalog — 506 voices after filtering — chosen in the same filterable, auditionable voice library
Soniox uses.

Cloning stops being a mode: it is one more entry in the voice list, shown only for the language
pairs the cloning model runs. The languages on offer no longer depend on the voice at all, because
every pair cloning runs is also a pair some fixed voice runs. The target language decides which
voices are listed; picking a voice never changes the language pair. One voice is remembered per
target language and persisted.

The catalog is a compact JSON snapshot committed to the repo, generated by a script we run with our
own Volcengine account keys. It never ships a key and is never fetched at run time.

## Findings that shaped this (verified 2026-09-28 → 2026-10-02)

Every finding below was measured against the live service with real speech, using frames built by
the branch's own code unless noted. Probe scripts are throwaway and not committed.

- **Two documents, two rule sets.** The AST 2.0 API document (docs 6561/1756902, updated
  2026-09-02) has a cloning mode ("声音复刻模式": sources and targets in lang_8, one side zh/en) and a
  fixed-voice mode ("指定音色模式": two named voices, sources lang_20 + dialects, "目标语种必须为中英").
  The TTS voice list (docs 6561/1257544) documents each voice's language.
- **The official proto was behind ours.** `ReqParams` gained `speech_rate = 5`,
  `is_custom_speaker = 7`, `tts_resource_id = 8` and more; landed in `0e0599bf`.
- **Each voice runs on exactly one `tts_resource_id`.** A wrong one ends the session with
  `55000000 resource ID is mismatched with speaker related resource`. With no `tts_resource_id`, an
  unknown `speaker_id` falls back to cloning silently.
- **The catalog is `ListSpeakers`** (OpenAPI `speech_saas_prod`, version `2025-05-20`, HMAC-signed
  with an account AK/SK): 564 entries, 548 voice ids, each with `ResourceID`, `Languages`, gender,
  age, categories, emotions and trial audio. It holds no account-specific voice (no `S_` clone) and
  matches the public voice-list page: 534 ids in common, 14 newer English voices only in the API,
  25 S2S-only `saturn_*` voices only on the page. Passing `Limit` returns 400 `InvalidParameter`;
  paging with `Page` alone works (10 per page).
- **A voice can speak several languages in two ways.** One entry listing several (only
  `zh_female_vv_uranus_bigtts`: zh-cn, ja, id, es-mx), or one id split over several entries, one
  per language, each with its own persona name and trial clip (16 ids: `zh_male_jingqiangkanye_moon_bigtts`
  is 京腔侃爷 in Chinese and Harmony in English; one of them even differs in age). Merged per id:
  531 voices have one language, 16 have two, one has four.
- **AST accepts every TTS catalog voice** on its own resource (a no-audio StartSession sweep of all
  559 page voices; S2S-only `*_jupiter_*` voices are refused). Acceptance at start is not enough: a
  one-way-only voice starts and then fails at the first sentence.
- **The voice list documents one-way-only voices**: its remark "仅限单向流使用，不支持双向流，双向流调用会
  直接报错" marks 15 rows, though the page's note says 16. `ja_female_minimi_uranus_bigtts`, one of
  them, failed exactly so in AST ("does not support the tts/bidirection API").
- **The two modes are enforced server-side, not just documented.** Cloning: ko→en, yue→zh, zh→ko,
  zh→th, zh→ru all fail with `group model:volc_tob-<src>2<tgt>-s2s not found`. Fixed voice: ko→en,
  yue→zh, zh→ko (with a Korean voice) run.
- **Fixed-voice targets beyond the document's zh/en, by language, not by voice.** zh→ja (16 of 17
  Japanese voices, the 17th being minimi), zh→es, id, pt, fr, de, ko run in a matching voice. zh→th,
  vi, ru, ar, ms fail with `45000001 unsupported speaker id <id>` with two different voices each
  (ar and ms with one). ja→ko fails with `unsupported source or target language`: one side must
  still be zh or en.
- **The fixed voice really speaks.** Median F0 against a ≈194 Hz female source: cloning ≈200–212 Hz;
  male fixed voices 108–180 Hz; female voices vary by voice. Billing units are the same as cloning's.
- **Trial audio is public CDN** (`lf3-static.bytednsdoc.com`) with `Access-Control-Allow-Origin: *`.
  Short trials are ~100 KB mp3; a few voices only have a 1.5 MB wav.

## Rulings (the user's, in order)

1. **R1** — a voice speaks only the languages its documentation lists, even if a probe shows more;
   a probe may only narrow (memory `sokuji-voice-languages-as-documented`).
2. **R2** — open the catalog by each voice's documented languages, exclude one-way-only voices, and
   drop the AST document's "fixed-voice targets must be zh/en" rule.
3. **R3** — filters: language, gender, age (not scene categories).
4. **R4** — the target language decides the voice list; picking a voice never changes the pair.
5. **R5** — one voice remembered per target language, persisted.
6. **R6** — catalog order is `ListSpeakers` order; no voice is promoted.
7. **R7** — cloning is a peer entry in the voice list, not a mode; it appears only where cloning
   runs the pair.
8. **R8** — the snapshot keeps only fields the app uses, and stays small.
9. **R9** — the whole catalog ships in the #577 branch as one PR (option B), not after a two-voice cut.

## 1. The catalog snapshot

### 1.1 Generation

The first snapshot is built from the `ListSpeakers` pull already made on 2026-10-02; nothing is
fetched again to land this feature. Two maintainer-only scripts under `scripts/doubao-voices/`:

- `fetch.py` — the script that made that pull: Volcengine's official Python SDK
  (`volcengine-python-sdk`, installed in a throwaway venv, never a repo dependency) signs
  `ListSpeakers` with `VOLC_AK` / `VOLC_SK` from the environment, pages it with `Page` alone (no
  `Limit`, which the service rejects) and writes the raw dump to a path given on the command line.
  Run only to refresh.
- `build.ts` — `npx tsx scripts/doubao-voices/build.ts <dump.json>` turns a raw dump into
  `src/providers/volcengine_ast2/voices.json` through a pure `buildCatalog(entries)` exported for
  tests.

The raw dump (589 KB) is not committed; `voices.json` is. CI runs neither script and no key is ever
committed. A refresh is `fetch.py` then `build.ts`, and an ordinary PR whose diff is the JSON.

`buildCatalog`'s rules, each commented with its source:

1. **Exclude one-way-only voices** — the 15 ids the voice-list remark column marks, listed in the
   script (the page says 16; the table marks 15 — the comment records the discrepancy).
2. **Map languages to app codes** — `zh-cn`/`zh` → `zh`, `es-mx`/`mx` → `es`, `pt-br` → `pt`, the
   rest as they are (`ja`, `en`, `id`, `fr`, `de`, `ko`, …).
3. **Keep only the targets a fixed voice can speak** — `zh en ja es id pt fr de ko` (§2.2). `th vi ru
   ar ms` are measured failures; `fil` has no AST code; `it` and `tr` have no surviving voice.
4. **Merge entries by voice id**; languages become a map under the voice.
5. **Add zh and en to the two voices the AST document names** (`zh_female_vv_uranus_bigtts`,
   `zh_male_jingqiangkanye_emo_mars_bigtts`): the AST document is their documentation for AST (R1),
   so Vivi has zh, en, ja, id, es and 京腔侃爷 (emo) zh, en.
6. **Drop a voice left with no language.**
7. **Keep `ListSpeakers` order** (R6).

Expected yield on the 2026-10-02 pull: 506 voices — zh 362, en 95, es 21, ja 16, id 14, pt 12,
fr 3, ko 3, de 1; 12 speak both zh and en.

### 1.2 Shape

```json
{
  "v": 1,
  "fetched": "2026-10-02",
  "prefix": "https://lf3-static.bytednsdoc.com/obj/eden-cn/lm_hz_ihsph/ljhwZthlaukjlkulzlp/",
  "voices": [
    { "id": "zh_male_jingqiangkanye_moon_bigtts", "r": 1, "g": "male",
      "l": { "zh": { "n": "京腔侃爷", "a": "middle_aged", "p": "portal/bigtts/short_trial_url/京腔侃爷.mp3" },
             "en": { "n": "Harmony", "a": "young", "p": "portal/bigtts/short_trial_url/Harmony.mp3" } } }
  ]
}
```

- `r` — resource: `1` → `seed-tts-1.0`, `2` → `seed-tts-2.0`.
- `g` — `male` | `female`, the voice library's existing gender vocabulary.
- `l` — per app language: `n` the persona name, `a` the age, `p` the trial clip path under `prefix`
  (short trial preferred, the long one only when no short exists).
- `a` — `child` | `teen` | `young` | `middle_aged` | `old`, from 儿童 / 少年/少女 / 青年 / 中年 / 老年;
  the last three are the library's existing values.
- A language entry identical to the voice's first one (Vivi's five) is stored as `{}` and read as
  that first entry.
- Dropped: avatar, emotions, description, labels, categories, the long trial when a short exists.

About 80 KB as written, ~11 KB gzipped. It is imported statically by the provider, so it lands in
the provider's chunk.

### 1.3 Reading it

`src/providers/volcengine_ast2/catalog.ts` wraps the JSON:

- `voicesFor(target)` — the voices that speak `target`, in catalog order, each as
  `{ id, resource, gender, age, name, previewUrl }` for that language; for `zh+en`, the voices that
  speak both, named and previewed in `zh`.
- `voiceById(id)` and `speaks(id, target)`.
- `defaultVoice(target)` — `voicesFor(target)[0]`.

A test pins the snapshot's invariants: every voice has a resource and a known gender and age, every
language key is one of the nine, every `p` is non-empty, ids are unique, and the one-way-only ids
are absent.

## 2. Languages and voices

### 2.1 Languages no longer depend on the voice

With cloning a peer entry (R7), `ast2Languages` returns one offer per context:

| | text only (unchanged) | speaking |
|---|---|---|
| sources | lang_20, the two dialects, `zh+en` | lang_20, `yue`, `wuu`, `zh+en` |
| targets of `zh+en` | `zh+en` | `zh+en` |
| targets of `zh` / `en` | lang_20 but itself | the nine fixed-voice targets but itself |
| targets of anything else | `en`, `zh` | `en`, `zh` |

Every pair cloning runs (lang_8 both sides, one of them zh/en) is in the speaking offer, so no pair
a user runs today disappears. The speaking offer stays within the text-only one (the registry's
invariant), and the guard `ast2Offers(direction, s, context)` reads the same two functions.

The `voice` field `96feb2ef` added to `languages` is removed: the offer no longer reads it.

### 2.2 Which pairs cloning runs

`clonable(pair)` — both sides in lang_8 (`zh en ja id es pt de fr`) with one of them zh or en, or
`zh+en` on both. Every other speaking pair needs a fixed voice. The dialects, the twelve other
lang_20 sources and `ko` as a target are fixed-voice only.

### 2.3 The voice list

For the run's pair (the host's `pair`):

1. **Clone the speaker's voice** — first, only when `clonable(pair)`.
2. Every `voicesFor(pair.target)` entry, named in the target language.

### 2.4 Settings and the effective voice

`Ast2Settings` gains one field, replacing `96feb2ef`'s `voice`:

```ts
/** The voice chosen per target language (#577 R5): 'clone' or a catalog voice id. */
voices: Partial<Record<FixedTarget, 'clone' | string>>;   // default {}
```

`FixedTarget` is the nine targets plus `zh+en`. It persists through the store's ordinary per-field
write (`settings.volcengineAST2.voices`); an object round-trips both in Electron's localStorage
(JSON) and in `chrome.storage.sync` (a ~500 B value, far under its 8 KB per-item quota).

`effectiveVoice(pair, s)`, used by both the picker and `build`:

1. `s.voices[pair.target]`, if it is `'clone'` and `clonable(pair)`, or a voice that
   `speaks(id, pair.target)`;
2. else `'clone'` when `clonable(pair)` — so every profile from before this feature, which has no
   `voices`, keeps cloning;
3. else `defaultVoice(pair.target)`.

The picker shows the effective voice as selected; choosing an entry writes `voices[pair.target]`.
A fallback never writes: a stored `'clone'` for English survives a ko→en run (where it cannot apply
and Vivi is used) and applies again on zh→en.

`migrateAst2Settings` keeps a stored `voices` entry only when its key is a `FixedTarget` and its
value is `'clone'` or a catalog voice that speaks that key; anything else is dropped, so a voice
removed by a snapshot refresh falls back by rule 2 or 3. No migration code for `96feb2ef`'s
`voice`: it never shipped.

### 2.5 The session

`buildAst2` resolves `effectiveVoice(context.direction, s)` on a speaking leg. A catalog voice adds
`voice: { speakerId, ttsResourceId }` to the config (resource from `r`); `'clone'` adds nothing. A
text-only leg never carries a voice. `startSessionFrame` and the adapter stay as `96feb2ef` made
them: the frame names `speaker_id` and `tts_resource_id` only for a fixed voice, so cloning and text
only send the bytes they always did.

The participant leg runs the reversed pair and so resolves its own target's voice from the same
`voices` map. The guard refuses a pair `ast2Offers` does not offer, and — never expected, as a
backstop — a speaking leg whose effective voice cannot run it.

## 3. The settings view

`Ast2SettingsView` replaces its `VoiceField` with the shared `VoiceLibrarySection`:

- `voices` — the §2.3 list as `VoiceEntry`s: the catalog voice id as `id`, the persona name as
  `label`, `group: 'builtin'`, `previewable: true`, `meta.facets: { gender, age }`; the clone entry
  as `id: 'clone'`, not previewable, without facets.
- `capability: { importModes: [], facetFilter: true }` — search, gender and age (R3); no add, rename,
  delete or refresh. Language is not a facet: the target decides the list (R4).
- `selectedId` — `effectiveVoice(pair, settings)`; `onSelect` writes `voices[pair.target]`.
- `isSessionActive` from `disabled`.
- While a gender or age filter is on, the clone entry is hidden, as the library already hides every
  unclassified entry under a facet.
- A one-line hint under the section: the voice applies only when the translation is spoken.

`VoiceField`'s `hint` prop (`e498b871`) stays — it is a small, tested, general addition — but the
AST2 view no longer uses `VoiceField`.

## 4. Preview

`onPreview(id)` fetches `prefix + p` for the run's target language, decodes it with
`AudioContext.decodeAudioData`, and returns the samples the section already plays through its
preview route. A failed fetch or decode is reported once with `reportError` and returns `null`; the
control re-enables. The clip is Volcengine's own sample sentence in that persona's language.

## 5. Extension CSP

`extension/manifest.json` `connect-src` gains `https://lf3-static.bytednsdoc.com`, pinned by a new
assertion in `manifest.consistency.test.ts`. Electron and the web build set no CSP; the CDN answers
`Access-Control-Allow-Origin: *`.

## 6. Strings

In all thirty locales:

- `voiceLibrary.filter.age.child` and `.teen` (the only new facet values).
- `providers.volcengine_ast2.voiceHint` reworded to the speech-only sentence.
- `providers.volcengine_ast2.voiceFemale` / `voiceMale` removed; `voiceClone` kept for the clone entry.

## 7. Tests

- `buildCatalog`: exclusion, language mapping, the nine-target filter, merging split entries, the
  AST document's additions, empty voices dropped, order kept — on a small fixture.
- The snapshot invariants (§1.3).
- Languages: the table in §2.1; every clonable pair offered; the registry invariant; `ast2Offers`.
- `clonable` and `effectiveVoice`'s three rules, including a stored `'clone'` surviving a non-clonable
  pair.
- `migrateAst2Settings` on `voices`.
- `buildAst2`: a catalog voice's speaker and resource; cloning and text only carry none; the
  participant leg's own target.
- The view: list contents with and without the clone entry; selection writes per target; facets on.
- Preview URL composition and the failure path.
- The CSP assertion.

Live, with the branch's own frames: zh→en clone; zh→en Vivi; zh→ja a Japanese voice; ko→en with no
clone entry and the default voice.

## 8. Out of scope

- Scene categories, emotions, speech rate (`speech_rate`), `is_custom_speaker` and the account's own
  cloned voices.
- Fetching the catalog at run time, or from the backend.
- Text-only runs, which never speak.

## 9. What changes on the branch

- `0e0599bf` (proto) stays as is.
- `96feb2ef`: `AST2_VOICES`, `fixedVoice` and the `voice` field are replaced by the catalog,
  `voices` and `effectiveVoice`; its zh/en-only target rule is dropped (R2); the config, wire and
  adapter changes stay.
- `e498b871`: the `VoiceField` hint stays; the AST2 view's `VoiceField` becomes the library; the two
  voice-name strings go.

## 10. Open points

- The keys used for the 2026-10-02 pull are a sub-user's; whether to keep them for refreshes is the
